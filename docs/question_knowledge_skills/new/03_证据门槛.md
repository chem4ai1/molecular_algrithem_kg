# 03 · 证据到什么程度才算数

第三个必须回答的问题：**我的结论能说到多硬？**
这决定了你能用哪个动词：proven / supported / suggests。

## 3.1 三档保真度与措辞

| 档 | 达成条件 | 可以说 | 不能说 |
|---|---|---|---|
| symbolic | 全链推导逐步机器验证 | proven / established | — |
| numerical | 有重复（≥2 seeds）+ baseline + 方差 | supported / confirmed numerically | proven |
| qualitative | 只有定性理由、单点、无方差 | suggests / consistent with | supported、proven |

**主结果（primary）至少 numerical；次要结果（消融、鲁棒性）可以 qualitative。**

这一条最容易犯的错：只有单 seed 的一次运行，却写 "our method improves X by 3%" ——
审稿人会直接问：「另外两个 seed 呢？」

## 3.2 证据充分性五项（审稿人真正在意的）

| 检查 | 底线 | 失败长什么样 |
|---|---|---|
| 统计功效 | 报告样本量/训练规模 + 最小可检测效应 | 「underpowered」：规模太小，效应看不出来 |
| 效应量 | 报效应量本身，且 >1× between-seed std | 「effect_within_noise」：提升还没 seed 抖动大 |
| 重复性 | ≥3 seeds 的 mean±std（lite ≥2） | 「single_seed」：单点不能支撑主结论 |
| 数据规模匹配 | toy/合成数据只能支撑「在测试的 regime 内」 | 「toy_overreach」：小数据结论当通用结论 |
| baseline 对比 | 主结论需同条件 ≥1 baseline | 「no_baseline」：只跟自己比 |

任一项失败 → 该结论只能降到 qualitative，不能进正文当主结果。

## 3.3 验证路由：先决定「怎么验证」

| 路由 | 触发 | 验证链 |
|---|---|---|
| experiment-first（默认） | 证据类型属 correlational/causal/simulational/experimental | 先 toy 快验（~20 轮量级）→ 主实验 → 强制实验矩阵；理论推导降为可选 |
| theory-only（例外） | derivational 且无数据、无可执行计算 | 证明为主 + 逻辑审计；鼓励做 toy 数值 sanity check |
| hybrid（显式声明） | 贡献同时依赖定理与实验 | 两条线并行，都算主验证 |

纪律：**拿不准就走实验**，因为绝大多数论文都有能跑的东西。

## 3.4 三层过滤（先便宜后贵）

做研究时不必每个想法都跑全量实验，但**主结论不能停在前两层**：

| 层 | 花多少 | 能证明什么 | ML 的具体化 |
|---|---|---|---|
| 低保真 | 文本推理 | 想法自洽、与文献不冲突 | 读摘要/表格，看趋势是否可能 |
| 中保真 | 代理实验 | 方向对不对 | `trend_score`：proxy epoch 上 val_loss 低于 baseline → 1.0；差 5% 内 → 0.5；差 >5% → 0；另查 `gradient_health`（NaN/爆炸） |
| 高保真 | 全量实验 | 结论可发表 | 完整矩阵 + seeds + 方差 |

中保真评分（ML 具体化）：`0.4×core_claim_support + 0.3×reproducibility + 0.3×resource_efficiency`。

> 这一层的作用：把 8–12 个想法在低/中保真筛掉 90%，只让 1–2 个进全量实验。
> 但它**不能**替你证明主结论 —— 中保真通过只说明「值得花全量实验的钱」。
