# 13 · 升级方向：语义层属性 → 应用层节点 → 决策链

> 把 `00`–`09` 的方法论知识点落成**可查询、可判定**的东西。
> 分三层递进：先补事实（S1 属性），再建可判定单元（S2 节点），最后连成决策链（S3）。

## 13.0 三层路线

| 层 | 做什么 | 产出 | 谁用 |
|---|---|---|---|
| S1 语义层属性 | Paper/Algorithm/Benchmark 加事实字段 | 图里能查到「这篇属于哪种范式、认什么证据」 | 抽取、复现、生成 |
| S2 应用层节点 | 把可判定的单元提升为节点 | Contribution / ExperimentArm / Assumption / FailureMode / EvidenceNorm / FigureAsset / CitationCheck / SectionPlan / ReviewPoint | 论文生成、审稿预演 |
| S3 决策链 | 事实 → 规则 → 建议 | 措辞许可 / 缺失实验 / 失败模式检查 / 论证支撑 / 图表归属 | 生成侧直接消费 |

为什么必须先 S1 再 S2：S2 的节点要靠 S1 的属性判定
（没有 `evidence_type` 就不知道要挂哪类 FailureMode）。

## 13.1 S1：语义层属性扩展

### Paper（+6）

| 属性 | 类型 | 来源 | 谁消费 |
|---|---|---|---|
| paradigm | formal/empirical/design/interpretive | 01 | 证据门槛、写作结构 |
| evidence_type | causal_inference/derivational/experimental/simulational/correlational/interpretive | 02 | FailureMode 选择、章节硬要求 |
| evidence_norm | 该领域认什么指标 | 02 | 指标对口校验 |
| contributions[] | 提升为节点（见 S2） | 04 | 贡献判定 |
| figures[] | [{label,caption,kind,for_contribution}] | 08 | 图表归属链 |
| section_map | [{section,claims[]}] | 06 | 论证支撑链 |

### Algorithm（+3）

| 属性 | 类型 | 来源 | 谁消费 |
|---|---|---|---|
| assumptions[] | 方法成立前提 | 07 | Type II 泄露 |
| novelty_basis[] | technical_constraint / theoretical_blind_spot / data_availability | 04 | 新颖性判定 |
| is_novel_component（Module 级） | bool | 05 | 消融规划 |

### Benchmark（+4）

| 属性 | 类型 | 来源 | 谁消费 |
|---|---|---|---|
| protocol | {seeds,split,eval_script,epochs,hardware} | 05 | 证据门槛（能否 numerical） |
| metrics[].contribution_link | 指向某条贡献 | 07 | Type III 代理不匹配 |
| metrics[].direction_source | explicit / heuristic | 03 | 措辞降级 |
| failure_modes[] | 适用本基准的失败模式 id | 07 | 审稿预演 |

**S1 不改 `stable_key()`**，历史 `spec_hash` 与 5 套复现产物不受影响。

## 13.2 S2：应用层节点（9 个）

| 节点 | 关键属性 | 关系 | 来源 | 消费场景 |
|---|---|---|---|---|
| Contribution | statement / kind / novelty_basis[] / section / claimed_strength | Paper-DECLARES->；-TESTED_BY->ExperimentArm | 04 06 | 贡献判定、摘要/引言写作 |
| ExperimentArm | kind(main/baseline/ablation/hyperparam) / name / config / n_seeds | Paper-RUNS->；-ON->Benchmark；Contribution-TESTED_BY- | 05 | 实验矩阵完备性 |
| Assumption | statement / scope(global/module) / applicability | Algorithm-ASSUMES->；-TESTED_BY->ExperimentArm | 07 | Type II 泄露、限制章节 |
| FailureMode | name / severity(fatal/high) / detection / domain_tags | EvidenceNorm-APPLIES-> | 07 | 审稿预演、自检清单 |
| EvidenceNorm | evidence_type / accepted_metrics[] / min_fidelity | Paper-CONFORMS_TO-> | 02 03 | 指标对口、措辞许可 |
| FigureAsset | label / caption / kind / for_contribution / placement(body/appendix) | Contribution-SHOWN_BY-> | 08 | 图表归属链 |
| CitationCheck | doi / venue / year / existence / metadata_ok / context_ok | Paper-CITES-> | 08 | 引用三层验证 |
| SectionPlan | section / claims[] / evidence_refs[] / word_budget | Paper-OUTLINES-> | 06 | 论证支撑、篇幅控制 |
| ReviewPoint | axis(6 维) / attack / response / severity | Contribution-CHALLENGED_BY-> | 09 | 最强反驳预演 |

每个节点回答一个具体问题：

| 节点 | 回答的问题 |
|---|---|
| Contribution | 这篇到底贡献了什么？每条贡献有没有实验支撑？ |
| ExperimentArm | 实验矩阵齐不齐？缺哪一类？ |
| Assumption | 方法在什么前提下成立？这些前提验证了吗？ |
| FailureMode | 这类研究最容易犯什么错？我有没有犯？ |
| EvidenceNorm | 这个领域认什么指标？我的指标对口吗？ |
| FigureAsset | 这张图该放正文还是附录？它支撑哪条贡献？ |
| CitationCheck | 这条引用是真的吗？它真的支撑这句话吗？ |
| SectionPlan | 这一节要论证什么？每个论断有证据吗？ |
| ReviewPoint | 审稿人会怎么打？我能回应吗？ |

## 13.3 S3：决策链（论文生成直接用）

一条链 = 输入事实 → 规则 → 输出建议。全部**确定性可算**，零 LLM。

### L1 措辞链

```
输入：Paper.evidence_type + Entry.seeds + Benchmark.protocol.seeds + 是否有 baseline
规则：symbolic → proven；numerical(≥2 seeds+baseline) → supported；否则 qualitative
输出：allowed_wording[] / forbidden_wording[]（写正文时直接查表）
```

### L2 实验完备链

```
输入：Contribution.kind + AlgorithmModule.is_novel_component + ExperimentArm[]
规则：baseline ≥3（含 naive）、ablation ≥ 创新组件数、hyperparam ≥3 点
输出：missing_arms[] + 补实验建议
```

### L3 指标对口链（Type III）

```
输入：Contribution.statement + EvidenceNorm.accepted_metrics + metrics[].contribution_link
规则：指标不在领域认可集 或 未指向该贡献 → 不对口
输出：misaligned_metrics[] + 建议补什么测量
```

### L4 失败模式链

```
输入：Paper.evidence_type → EvidenceNorm → 适用 FailureMode[]
规则：逐条检查（如 simulational 查收敛/数据泄漏/baseline配置/指标错配/seed挑选/规模越界）
输出：risk[]（hit/miss/unknown）+ 每条的自检动作
```

### L5 论证支撑链

```
输入：SectionPlan.claims[] → 每条 claim 的 evidence_refs
规则：claim 指不到表格行/图/统计检验 → 无支撑
输出：unsupported_claims[] + 降级建议（改为 we observe / 删）
```

### L6 图表归属链

```
输入：FigureAsset.kind + for_contribution
规则：主对比/主消融 → 正文；次要鲁棒性/全量网格 → 附录
输出：placement + 理由（删掉会削弱哪条贡献）
```

### L7 审稿预演链

```
输入：Contribution + 支撑证据 + L4 的 risk
规则：按 6 维（新颖/有效/严谨/影响/可复现/表达）生成最强反驳
输出：attacks[]（按 severity 排序）+ 可回应性（能补/只能降级/无法回应）
```

## 13.4 每个阶段：必需知识点 → 落地物 → 支撑的链

| 阶段 | 必须回答的问题 | 必需知识点 | 落成什么 | 支撑链 |
|---|---|---|---|---|
| 01 范式 | 我的结论靠什么成立 | 四种范式的真值标准与兜底 | Paper.paradigm | L1 |
| 02 证据类型 | 这个领域认什么证据 | 六类 evidence_type 的验证方法与章节硬要求 | Paper.evidence_type、EvidenceNorm | L1 L3 L4 |
| 03 证据门槛 | 能说到多硬 | 三档保真度、证据充分性五项、验证路由、三层过滤 | Benchmark.protocol、Entry.seeds、fidelity | L1 |
| 04 贡献判定 | 凭什么说这是新的 | why-not-before 三类、碰撞矩阵、打分与淘汰线 | Contribution、Algorithm.novelty_basis | L2 L7 |
| 05 实验设计 | 实验够不够 | 矩阵四类、baseline ≥3（含 naive）、消融 ≥2、seed 策略、阶梯 | ExperimentArm、Module.is_novel_component | L2 |
| 06 论证结构 | 每章为哪个结论服务 | 摘要五句、引言四段、正文附录归属、篇幅预算、冗余 | SectionPlan、Paper.section_map | L5 L6 |
| 07 失败模式 | 本领域哪些错致命 | 六种 ML 致命坑 + 各类型专属坑 | FailureMode、Benchmark.failure_modes | L4 L7 |
| 08 图表引用 | 图/引用能否支撑那句话 | 图表四规则、引用三层验证、符号表格规范 | FigureAsset、CitationCheck | L5 L6 |
| 09 审稿视角 | 审稿人会怎么打 | 阅读顺序、最强反驳、六维打分、意见处理 | ReviewPoint | L7 |

**结论**：S2 的 9 个节点不是随意加，而是每份文档至少对应一个；
缺哪个节点，对应的那条链就断了。

## 13.5 索引：生成时怎么找得到

### 结构化索引键（等值查询，零成本）

| 键 | 取值来源 | 典型查询 |
|---|---|---|
| `evidence_type` | Paper | 同类论文的贡献/限制写法 |
| `paradigm` | Paper | 该范式的章节结构 |
| `contribution.kind` | Contribution | method 类贡献的标准论证路径 |
| `arm.kind` | ExperimentArm | 同类方法的消融都做了什么 |
| `failure_mode.severity` | FailureMode | fatal 级坑优先自查 |
| `metric.contribution_link` | Benchmark.metrics | 该贡献通常用什么指标 |

### 向量索引

复用 `semantic/vector_sync.py`：新节点也入 BGE 索引（1024 维），
检索时按 `evidence_type` 先过滤再向量召回，避免跨领域串味。

### 三个高频检索场景

| 场景 | 查询 | 取回什么 |
|---|---|---|
| 写引言 | (evidence_type, contribution.kind) | 同类论文怎么陈述贡献、怎么讲 why-hard |
| 写限制 | (evidence_type, failure_mode) | 同领域怎么老实写限制 |
| 写方法 | (algorithm.family, module.role) | 同类模块怎么描述机理与输入输出 |

| 步 | 范围 | 改哪里 | 验收 |
|---|---|---|---|

## 13.8 一个完整例子：L1 措辞链

```
输入  Paper.evidence_type        = simulational
      Benchmark:zinc.protocol    = {seeds: null}     ← 原文没写几次重复
      Entry: MolMiner/validity   = 100.0（seeds=1）

规则  ① 无 seeds 或无 baseline → 不能判 numerical
      ② 单点结果 → fidelity 最高只能到 qualitative
      ③ qualitative → 只允许 suggests / consistent with

输出  allowed_wording  = ["suggests", "consistent with"]
      forbidden_wording = ["proven", "established", "supported", "improves"]
      写作建议 = "MolMiner achieves validity 100.0 under the reported setting"
```

这条链把 `03 证据门槛` 的三档保真度直接变成**写作时的硬约束**，
而不是靠作者自觉。同类链（L2–L7）都是同样的形态。
