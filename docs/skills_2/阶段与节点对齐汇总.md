## 3. 新增节点的二次收敛判断
各文件第 6 列给出的是「局部最优」建议。集中审查后，按知识图谱判据收敛为三层：

**判据**：需独立 id + 跨阶段读写 + 被单独查询 + 不能由现有节点的属性/边表达 → 才新增节点；
否则优先属性扩展；运行态与项目治理文档不进知识图。

### 3.1 第一层：应新增到 `applayer/tbox.py`（7 个）

| 新节点 | 生命周期 | 为什么现有节点不够 | 来源文件 |
|---|---|---|---|
| `Claim` | global + task-w | `Contribution` 只有 statement/kind/evidence，缺 `fidelity`、`outcome_class`；这是措辞门的唯一判据 | `result-to-claim`、`grounding-check`、`confidence-uplift`、`paper-voice-contract` |
| `ClaimAnchor` | task-r | 三哈希（code/input/output）需独立可复算单位，不是 Claim 的普通字段 | `result-to-claim` |
| `TDAL` | task-r | `joint = T×D×A×L` 是单一权威 schema，任一维为 0 就封顶；塞进 `FailureCheck.note` 会失去维度结构 | `domain-adaptation-contract`、`confidence-uplift`、`ouroboros-integration` |
| `IdeaDAG` | task-w | `IdeaNode` 无 multi-parent crossover 边，且需保存 mutation 谱系 / 三档 fidelity / UCB 状态 | `idea-discovery`、`idea-dag-schema`、`mcts-search-protocol`、`multi-fidelity-evaluation` |
| `FalsificationRecord` | task-w | `ReviewPoint` 面向论文反驳，不面向「想法级证伪尝试 + assumption_health」 | `adversarial-falsification`、`idea-discovery` |
| `MethodLock` | global | 预注册是方法承诺（hash + Section3 锁 + 实验矩阵），与 `Assumption`（前提）语义不同；不可进语义层 | `method-registry` |
| `VerificationRoute` | global | 需显式记录 `na_verdicts[]`（哪些门不适用及理由），Phase 16 据此判 verdicts_incomplete | `verification-routing` |

### 3.2 第二层：不新增类，改为属性 / 边属性扩展（12 项）

| 建议名（各文件原表述） | 收敛为 | 落点 |
|---|---|---|
| `FigureAudit` / `FigureBudget` | `FigureAsset.audit_verdict`、`FigureAsset.budget` | 图资产已有独立 id，审计结果作为属性即可 |
| `ExecutionSession` / `ExperimentRun` | `RunArtifact` 加 `session_id / code_hash / dispatch_id / status / outputs_sha` | 运行产物已有节点，不必按执行阶段拆分 |
| `S2Ladder` / `AblationLedger` | `ExperimentArm` 加 `critic_state / engineer_rounds / ablation_of` | 三者都是实验臂的评估态 |
| `ReviewState` / `ReviewLedger` / `KillArgument` / `RebuttalLetter` | `ReviewPoint` 加 `round / model_ids / trace_path / attack / response_class / still_unresolved` | 评审关注点已有节点；书信体文本落 `RunArtifact` 而非知识图 |
| `LeakageFinding` / `LogicIssue` / `CompileReport` / `PublishabilityScore` | `FailureCheck` 加 `check_type / severity / path / dimensions` | 自检结果已有 task-r 节点，扩展字段即可 |
| `DerivationStep` / `ProofAudit` | `Evidence` 加 `kind=derivation`、`expr / verified / tool / steps` | 推导结果本质是一类证据 |
| `GapReport` / `VerificationLog` | `SourcePaper` 加 `verification_layers / gap_id / priority` | 文献验证状态是来源论文的属性 |
| `ToolRegistration` | `CodeUnit` 加 `tool_hash / smoke_test / usage_count` | 工具就是代码单元 |
| `FrontierGap` / `CollisionAudit` | `ResearchGap` 加 `frontier_baseline / delta / why_not_before / collision` | 空白节点已有，缺的只是判定字段 |
| `IntakeManifest` | `HumanIntent` 加 `census / phase_plan` | 入口需求属于人类意图 |
| `FigureBudget` | `SectionPlan.figure_budget` | 预算是章节计划的一部分 |
| `CheckGroup` | `GateVerdict.checks[]` | 逐项证据是 verdict 的属性 |

### 3.3 第三层：明确不进知识图（4 类）

| 类别 | 文件 | 理由 |
|---|---|---|
| 运行态 | `auto-pipeline`（`RunState` / `RunBudget` / `LoopBack`） | 写 `.sciforge/RUNSTATE.json`、`.sciforge/verdicts/RUN_BUDGET.json` 即可；它们是运行控制，不是论文知识 |
| 项目治理 | `competitive-analysis`、`competitive-drift-monitor`、`domain-contribution-protocol` | 战略快照 / 季度监控 / PR 流程，不参与论文生成图 |
| 历史存档 | `reviewer-prompts/economics`、`reviewer-prompts/README` | 已迁移的 persona，现行由 `discipline-context.md` general 接管 |
| 纯约束法条 | 15 份 `全阶段·法条` | 它们规定判定规则，自己不产出知识节点 |

### 3.4 落地顺序建议

1. 先加 `Claim` / `ClaimAnchor` / `TDAL` —— 阶段 1→3→5 的主干，且被最多文件引用；
2. 再加 `IdeaDAG` / `FalsificationRecord` / `MethodLock` / `VerificationRoute` —— 阶段 0→2 的决策可追溯性；
3. 属性扩展可随第 1、2 步同批做，不需要单独版本；
4. 运行态与治理文档只补 schema 文档说明，不改 `tbox.py`。
