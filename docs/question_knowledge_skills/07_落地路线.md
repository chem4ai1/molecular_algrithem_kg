- 3 态 Critic 接入四环节（EXECUTION_LOG.ladder_state）

- 引用 3 层验证（existence/metadata/context）

### P2（4 项，生成侧）

- novelty 4 轴打分（0.45/0.25/0.15/0.15，<0.6 淘汰）
- adversarial falsification（假设攻击 + 反例）
- auto-review 3 轮角色切换
- 图表契约（复杂度/布局/调色板）

## 7.3 三条风险

1. **prompt 体积**：新增约束每阶段 ≤200 字符；6 阶段合计须 ≤10000（当前 8395）。
2. **hash 失效**：新增属性严禁进 stable_key()，否则 5 套已跑产物无法比对。
3. **过度约束**：seeds/protocol 缺失是合法的 null；强制填会诱导编造，
   应「缺则标记、不阻塞」而非「缺则报错」。

## 7.4 与其他文档的关系

- 05/06 是语义层/应用层与门控的落点

## 7.5 一句话总结

SciForge 提供的是「预注册 + 保真度 + 四类泄露 + 三档 Critic」这套**证据纪律**；
我方已有「语义层 → SAU → 四环节」这套**确定性骨架**。
两者结合点：把纪律写成 prompt 字段与门判据，而不是新增 LLM 阶段。
