# 05 · 语义层缺口与本体治理

现有 6 类 / 9 关系，6001 节点 / 7460 断言。原则：一句话能说清→属性；需任务聚合→应用层；跨论文查询→才进语义层。

## 5.1 四个缺口，三个不新增类

| 缺口 | 落法 | 理由 |
|---|---|---|
| B1 问题锚定 | Paper.problem_anchor={id,text,hash} | 属论文自身属性 |
| B2 实验协议 | Benchmark.protocol={seeds,split,eval_script,epochs} | 基准属性 |
| B3 引用权威 | RELATED_TO 边加 verified/doi/venue/context | 边属性足够 |
| B4 消融组 | 不进语义层 | 属运行时层 |

结论：仍 6 类 / 9 关系，只加属性不加类。

## 5.2 新增属性的校验

| 属性 | 校验 | 缺失后果 |
|---|---|---|
| problem_anchor.id | 形如 Q-2411.06608 | lock → blocked:no_problem_anchor |
| problem_anchor.hash | 由 text 归一计算 | 不一致 → problem_drift |
| protocol.seeds | 1–10 | lock 记 missing_protocol |
| metrics[].contribution_link | ≤20 字 | Type III 标 unlinked_metric |
| RELATED_TO.verified | 引用审计写入 | 未验证不计入 resolved |

## 5.3 与 INV-C1~C4 对应

| 不变量 | 落点 | 时机 |
|---|---|---|
| INV-C1 协议锁 | protocol + experiment_matrix | lock |
| INV-C2 消融完整 | 运行时 AblationRun | codegen 后 |
