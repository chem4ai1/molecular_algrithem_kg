# P3 · 阶段 7–10：结构审计、证据充分性与主张锚定

> 覆盖 26 节点：`7` leakage-audit ∥ `8` logic-verification → `9` invariant-check → `10` result-to-claim（3-fidelity + TDAL + ablation）。
>
> 语义层现状（实测）：`assertions[].attribution` **100% 为 `analyst_synthesis`**，`evidence_ids` **100% 空**；
> 证据只存在于 `assertions[].properties.evidence` 的逐字串，**没有 Paper 内位置指针**；
> `Benchmark.model_results` 只有 34% 的基准有（12835 条），`metrics` 78%（811 条，772 条有 `direction`）。
> 也就是说：**这一阶段是全链最脆弱的一段——所有「数字 → 话」的转换都发生在这里，而支撑它的证据层是最稀的。**

## P3.2 `fidelity_of()` 的确定性定义（本阶段唯一核心算法）

```python
def fidelity_of(e) -> tuple[str, str]:
    """返回 (fidelity, reason)。零 LLM。"""
    if e.value_num is None:
        return "qualitative", "no_numeric_value"
    if e.seeds is None or e.seeds < 2:
        return "qualitative", "single_seed" if e.seeds == 1 else "seeds_unknown"
    if not e.has_variance:
        return "qualitative", "no_variance_reported"
    if not e.has_baseline:
        return "qualitative", "no_baseline"
    return "numerical", ""
```

三条硬约束：

1. **`symbolic` 不由此函数产出**——只有 `DerivationStep` 全链机器验证才给 `symbolic`（见 P2 DK-P2-07）。
2. **`reason` 必填**——空的 downgrade 理由等于没降。
3. **不进 `stable_key()`**——`fidelity` 是判定结果，不是方法指纹。

## P3.3 本节小结（表外三件事）

1. **`evidence_ids` 100% 为空，是整批文档里最严重的一条。**
   它意味着 7460 条断言里**没有一条能指回原文位置**。
   后果不是「引用不够权威」，而是：Type III（指标是否度量贡献）、claim 锚定、citation context 三层校验**全部无法执行**。
   → 这条必须单独立项：`assertions[].properties.evidence_span`（C 类，不改类、不改关系）。

2. **`fidelity` 只该有 4 个输入：`value_num / seeds / has_variance / has_baseline`。**
   一旦引入「LLM 判断这条结果强不强」，三档保真度就变成主观打分，P4 的措辞门会随之失效。
   这也是为什么它必须是**纯函数 + 可单测**。

3. **TDAL 的 `A`（assumption）维不能独立打分。**
   它必须由 P2 的 `AssumptionLedger`（discharged 比例）与 P1 的 `assumptions[]` 共同决定；
   否则会出现「假设都没证，但 A 维给 0.9」。

## P3.5 反模式

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 用「抽查 20 条证据都有出处」代替 `evidence_span` | 抽查通过 ≠ 可判定；下一批论文仍无指针 | 结构性字段，抽取期必填，校验切片一致 |
| `has_variance` 用「有没有写 ±」判断 | `±0.01` 可能是 std 也可能是 CI 半宽 | 记录 `variance_kind ∈ {std, sem, ci95, range, unknown}` |
| 把 `outcome_class=primary` 交给 LLM 自由判断 | 主次是可被操纵的 | 由「是否出现在论文主表/首段结论」+ 人工确认共同决定 |
| Type IV 只比数值差（在 tolerance 内即 PASS） | 忽略了「是否在假设成立的 regime 内」 | 必须同时比对 `research_object / modality` |
| 门通过率异常升高时调阈值 | 掩盖真实缺口 | 阈值写 `config.yaml` 并由测试锁定 |
