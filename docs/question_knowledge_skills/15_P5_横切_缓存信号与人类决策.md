# P5 · 横切：缓存、探索信号、人类决策与回退预算

> 这一份不覆盖某个阶段，而是覆盖**贯穿全部 26 节点的四类横切问题**。
> 它们的特点是：不出现在任何单一阶段的产物里，但每一阶段都会遇到；一旦处理错，错误会**跨阶段累积且不可追溯**。
>
> 真实代码基线：
> - `src/capfactory/paperapp/nodecache.py::cache_identity()` —— 缓存身份 8 个维度（`task / stage / input_fp / semantic_fp / tbox_version / prompt_version / model_id / effort / decision_fp`）
> - `src/capfactory/paperapp/tbox.py::CHOICEPOINTS` —— 14 个决策点：`3 / 5 / 6b / 14` 为 `gate`，`1b / 4broad / 2 / 2.5 / 6 / 10 / 11 / 12 / 15.5` 为 `option`，`4targeted` 为 `advisory`
> - `src/capfactory/paperapp/signals.py` + `hitl.py` + `coverage.py`
> - `src/capfactory/semantic/extraction/vocab.py::observe/promote`

## P5.2 三类「看起来能省事、实际会毁掉可追溯性」的设计

| 设计 | 表面收益 | 真实代价 | 正确替代 |
|---|---|---|---|
| 缓存只按 `input_fp` 命中 | 命中率高 | 换模型/prompt/决定后复用旧结论 | 8 维身份（含 `decision_fp`） |
| 把 LLM 新节点直接写进 `app_generation.json` 参与判定 | 省一层 | 推测与事实混居，`verify_rebuild` 永远 DRIFT | `proposed → validated → registered` 四态，只有 `registered` 可用 |
| 人被 gate 卡住时给个默认值让它继续 | 流程不阻塞 | 人类主权名存实亡 | `BLOCKED` + 明显待办，宁可停 |

## P5.5 反模式

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 为提高命中率删掉 `decision_fp` 维度 | 人改主意后复用旧结论 | `decision_fp` 是硬门（`H15`） |
| 把 `dismissed` 信号物理删除 | 失去否定证据 | 只写 `dismiss_reason` |
| `gate` 超时用默认选项 + 事后补签 | 补签永远补不上（时间戳造假） | 直接 `BLOCKED` |
| 增量回写 DRIFT 时「以增量为准」 | 缓存变第二真相源 | DRIFT → 拒绝写入并要求全量重建 |
| 用 `human_boost` 提高人的方案通过率 | MCTS 失去意义 | 默认 0，且留痕 |
