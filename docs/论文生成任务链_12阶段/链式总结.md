## 1. 核心判断

一句话：**schema 是数据模型，skills 是状态转移函数，auto-pipeline 是解释器。**

- schema 定义了 6 类语义层节点（客观事实，6001 实例）+ 28 类应用层节点（派生/判定/任务态，当前 0 实例）。
- 每个 skill 的真实契约是「读入节点 + 产物 → 用 prompt/法条推理 → 过门判定 → 写出节点 + 产物」。
- auto-pipeline 把 26 个 phase 串成 DAG，只做三件事：路由 skill、读 verdict、卡硬门并触发有界回退。它自己不做研究——**"The orchestrator is structural, not substantive."**

这套设计的表达力是足够的：用"节点 + skill + 门"三件套，能表达"某次论文生成中某条 claim 由哪个实验臂验证、措辞是否越级、引用是否错上下文"这类具体事实。但**当前应用层节点 0 实例**，说明这是设计蓝图而非已落地数据。

## 2. 三层配合机制

| 层 | 数量 | 角色 | 是否产出节点 |
|---|---:|---|---|
| meta-skills | 8 | 重能力（检索/想法/新颖性/绘图/领域学习/沙箱/工具） | 部分 |
| orchestrator | 1 | 26 节点 DAG 编排 | 运行态（GateVerdict/Lesson） |
| support | 19 | 阶段执行器（预注册/推导/实验/claim/写作/编译/审计/反驳） | 是 |
| shared-references | 55 | 法条层：注入 prompt 的判定规则 | 否（或被引用方回填字段） |

配合的"化学反应"是一个阶段 = **读入节点 + 注入法条 + 跑脚本门 + 写回节点**：
- `paper-writing` 消费 paper-modes（哪些节）+ discipline-writing（怎么写）+ voice/language（语气）+ citation-discipline（引用），再跑 leakage_scan / claim_anchor_gate，写出 SectionDraft。
- **跨 skill 约束通道**：`result-to-claim` 产出的 `Claim.fidelity` 被 `paper-voice-contract` 消费，决定正文用 `proven`（symbolic）/ `supported`（numerical）/ `suggests`（qualitative）——节点字段成了跨 skill 的约束载体。
- 所有门结论统一成 6 态 verdict，编排器只读 verdict 决策。

## 4. 知识节点流转图

```
语义层（客观事实，永久）
  Paper ──PROPOSES_METHOD──▶ Algorithm ──HAS_MODULE──▶ AlgorithmModule
    │EVALUATED_ON                │EVALUATED_ON              │MODULE_IMPLEMENTED_BY
    ▼                            ▼                          ▼
  Benchmark ◀────────────────────┘                    CodeFunction
  Paper ──HAS_CODE──▶ CodeRepository ──HAS_FUNCTION──▶ CodeFunction

阶段1-2   ResearchQuestion / EvidenceNorm / FailureMode  ←── domain-learner
阶段3     SourcePaper / ResearchGap / CitedPaper         ←── universal-retrieval
阶段4-5   IdeaNode / ResearchGap(selected_at) / Contribution(候选) ←── idea-discovery + novelty-check
阶段6     Assumption / ExperimentArm / MethodLock        ←── method-registry
阶段7     Evidence / LeaderboardEntry / Claim / ClaimAnchor / TDAL / FigureAsset ←── 素材装配
阶段8     SectionPlan / SectionDraft / ConsultedPaper     ←── 起草
阶段9-11  ReviewPoint / FailureCheck / REBUTTAL_LETTER    ←── 复审/反驳
阶段12    CitedPaper(三层回填) / FailureCheck / Lesson    ←── 自检核验
```

**关键**：语义层节点是"被读"的事实源（Paper/Benchmark/AlgorithmModule/Evidence），应用层节点是"被写"的判定结果（Claim/SectionDraft/ReviewPoint/FailureCheck）。阶段 7 是两者交界的蒸馏区。

## 5. 门与有界回退总表

| 回退类型 | 触发 | 目标 phase | 上限 | 耗尽出口 |
|---|---|---|---|---|
| in_phase（执行错误） | 单 phase 失败 | 相邻上游 | 3 轮（per-failure-type） | BLOCKED + reason_code |
| BA（实验证伪想法） | 6c full FAIL / 8 logic FATAL / 14 kill | Phase 2 换想法 | ≤2 轮（全局共享 L7/L9/L11） | BLOCKED + BA_EXHAUSTED |
| PIVOT | toy FAIL 但可换方法 | Phase 5 重注册 | ≤2 次 | 强制 KILL |
| KILL | kill-argument 成立 | Phase 2 换想法 | 人工检查点 | 停并呈人类 |
| LEAKAGE callback | Type I LEAKY on primary | method-registry | ≤3 轮 | DRAFT + LOGIC_GAP_FUNDAMENTAL_ISSUE |
| 复审循环 | effective_score<6 | Phase 6 补证据 | ≤4 轮 | BLOCKED |
| rebuttal | panel score<8 | rebuttal | ≤2 轮 | meta_review 裁决 |
| 编译 warning | 同一 warning | paper-compile | 3 次（按 warning 计） | BLOCKED，仅用户豁免 |
| 预算耗尽 | 成本/时钟达上限 | — | effort 档上限 | BLOCKED + budget_exhausted |

**6 态 verdict**：`PASS / WARN / FAIL / NOT_APPLICABLE / BLOCKED / ERROR`；整体 verdict = 最差值 `ERROR > BLOCKED > FAIL > WARN > NOT_APPLICABLE > PASS`。关键纪律："NOT_APPLICABLE means **the audit phase ran**, the detector returned negative"——不是静默跳过。

**反自欺三硬门**（pipeline-integrity 的 MUST/OPTIONAL/CONDITIONAL）：MUST phase 失败 3 轮即 BLOCKED；每 phase 执行前写 Pre-Flight Log。
