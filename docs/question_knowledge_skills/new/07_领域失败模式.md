# 07 · 这个领域必须避免的错

第七个必须回答的问题：**我的研究方式有没有踩到本领域的经典坑？**
SciForge 维护了一份按证据类型分类的失败模式目录，每条都有检测方法与严重度。

## 7.1 ML / simulational 最常见的六种

| 失败模式 | 长什么样 | 怎么发现 | 严重度 |
|---|---|---|---|
| 收敛失败 | 迭代没收敛到真解，却当成结果 | 报收敛曲线、多起点 | fatal |
| 数据泄漏 | 训练集里混入测试样本 | 查划分脚本、重复样本 | fatal |
| baseline 配置不当 | 对手用默认参数、你用调优参数 | 同条件、同搜索预算 | fatal |
| 指标错配 | 用 accuracy 证明「表示更好」 | 指标与贡献的对应关系 | fatal |
| seed 挑选 | 只报最好的 seed | 要求 mean±std 与全部 seed | fatal |
| 规模越界 | toy 结果当通用结论 | 声明「在测试的 regime 内」 | 高 |

这六条里任何一条被审稿人抓到，基本等于拒稿 —— 因为它们不是「写得不好」，是「结论不成立」。

## 7.2 其他证据类型的专属坑（跨领域时用）

| evidence_type | 典型失败模式 |
|---|---|
| causal_inference | 遗漏变量、选择偏差、反向因果、工具变量不成立 |
| correlational | 幸存者偏差（只分析活下来的）、混杂未控制 |
| derivational | 隐含假设未声明、定理条件未验证、证明跳步 |
| experimental | 功效不足、未盲法、排除标准事后调整 |
| simulational | 收敛失败、分辨率不足、不确定性未量化 |
| interpretive | 选择性引用、替代解释未讨论、循环论证 |

## 7.3 怎么用这份目录

1. 先定 `evidence_type`（见 02）
2. 取出该类型下的全部失败模式
3. 对每条问：**我这项研究有没有这个风险？**
4. 有风险的，要么在设计阶段消除，要么在限制章节里如实声明

> 目录不完整，且新问题会带来新坑。它的价值在于强迫你逐条检查，
> 而不是提供一份完整清单。
