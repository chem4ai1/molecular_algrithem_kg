# 04 · 什么算「新」

第四个必须回答的问题：**凭什么说这是新的？**
这是审稿人第一个打的地方，也是最容易自我欺骗的地方。

## 4.1 新颖性不等于「没人做过」

必须能回答「为什么以前没人做」—— 且理由要落在三类的至少两类：

| 类别 | 例子 |
|---|---|
| 技术约束 | 之前算力/框架不支持（如 3D 几何在大模型前不可行） |
| 理论盲点 | 领域普遍假设了某个前提，但它是错的 |
| 数据可得性 | 之前没有这个数据集/标注 |

如果三条凑不出两条，说明「没人做过」很可能是因为**这件事没意义**，
不是因为你发现了空白。这种情况标记 `why_not_before_weak`。

## 4.2 碰撞矩阵：和已有工作到底差在哪

对最近 5 篇最相关论文逐篇打 0/1：

| 维度 | 0 | 1 |
|---|---|---|
| same_problem | 研究问题不同 | 同一个问题 |
| same_method | 方法族不同 | 同族，仅组件差异 |
| same_data | 数据不同 | 同一 benchmark |

- 三维全 1 → 撞车，必须重定位
- 两个 1 → 增量工作，需说明「这个组件为什么关键」
- 一个 1 → 可用，但仍需解释差异

## 4.3 综合打分（决定要不要做）

```
score = novelty*0.45 + feasibility*0.25 + relevance*0.15 + engineering_grounding*0.15
score < 0.6 → 淘汰
```

## 4.4 什么不算贡献

| 常见说法 | 为什么不算 |
|---|---|
| 把 X 换成 Y，涨了 2 个点 | 组件替换，除非证明这个替换为什么必要 |
| 在更多数据集上评估 | 换数据不等于新方法 |
| 我们开源了代码 | 工程贡献，不是科学贡献 |
| 我们做了大规模实验 | 工作量不是贡献 |
