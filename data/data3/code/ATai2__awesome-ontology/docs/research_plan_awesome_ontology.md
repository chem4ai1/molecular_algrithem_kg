# 研究计划：awesome-ontology 工程

## 目标

参考 semantalytics/awesome-semantic-web，在 `d:/code/awesome-ontology` 从零构建一个 awesome 清单工程，主题为本体工程（Ontology Engineering），面向中文读者，资源以国际一手资料为主。

## 查询类型判定

属于**广度优先（breadth-first）**查询：可分解为若干相互独立、可并行研究的子主题（工具链、本体与词表、平台与标准、学习资源与社区），最后聚合为一份结构化清单。

## 研究子任务与分工

| 子任务 | 覆盖范围 | 预期产出 |
| --- | --- | --- |
| A 工具链 | 编辑器、推理机、编程库、可视化、文档生成、质量评估、匹配对齐、本体学习与 LLM 辅助建模、版本与模块化、三元组库 | 每子类 6-15 条，含名称、URL、语言、许可证 |
| B 本体与词表资源 | 顶层本体、通用词表、生物医学、地理空间、工业制造、金融法律政务、学术出版、农业食品、其他垂直领域、中文与国产资源 | 每子类 6-15 条，含形式化程度与许可 |
| C 平台标准与基准 | 本体仓库与检索平台、W3C/ISO/国家标准、社区最佳实践、基准数据集与评测 | 30-50 条，标注标准状态 |
| D 学习资源与社区 | 书籍、课程、会议期刊、组织与人物、博客与 Newsletter、相关 awesome 列表 | 40-70 条 |

## 信息检索策略

第一选择是 `web_search` 加 `web_fetch` 做一手核验，并用 `wechat-article-search` 技能补充微信公众号文章，用于发现中文语境下的本体工程实践与工具动态（检索关键词："本体工程"、"知识图谱 本体建模"、"Ontology LLM"，时间范围 2023 至 2026 年）。微信公众号文章用于发现线索与交叉验证趋势，正式收录仍以官方站点与仓库为准。

## 执行约束与实际情况

计划启动时发现本机外网直连不可用：`curl` 对 github.com 与 raw.githubusercontent.com 返回 000，`web_fetch` 两次请求超时，研究子代理因 API 域名解析失败（getaddrinfo ENOENT）无法启动，仅 `web_search` 通道可用。

因此调整为：以既有领域知识构建清单主体，再用可用的 `web_search` 通道对不确定链接做抽样核验，最后通过 `scripts/check_links.py` 与 GitHub Actions 的定期链接检查把"链接可达性"变成可持续执行的工程机制，而不是一次性人工核对。

待办（由后续维护者或联网环境执行）：全量链接巡检、按 `.lycheeignore`/`ignore-links.txt` 放行反爬站点、补齐尚未收录的中文社区资源。
