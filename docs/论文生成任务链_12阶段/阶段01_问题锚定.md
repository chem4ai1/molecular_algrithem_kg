# 阶段 01 · 问题锚定（对齐 SciForge Phase 0 / 1 / 1a）

> 定位：接收人类给出的一个问题，分类投递物、冻结 Q-id（INV-G1 锚点），并抽取一个临时的领域签名 hint。它是整条链的入口，本身不做研究。

## 1. 处理的问题（事实）

- `intake-triage`：把用户交付的任意组合（裸问题、草稿、代码、数据、结果、日志、目标期刊）普查分类并路由。**"It plans; it never weakens a gate"**——只规划，不削门。
- `domain-signature`：从问题文本用规则抽取领域特征 hint，作为 Phase 1b learner 的 prior。**"Core philosophy: Do NOT hard-code domain classification. Let the agent discover domain characteristics at runtime from the problem's own language, literature, and structure."**
- 冻结动作：Phase 0 把 Q-id 写进 `FINAL_PROPOSAL.md` 并计算问题段落 SHA256 到 `PROBLEM_HASH.txt`（INV-G1）。

## 2. 输入

### 2.1 检索的知识节点
| 节点类 | 关键属性 | 来源 | 是否必须 |
|---|---|---|---|
| Problem（用户 prompt） | `qid / text / description` | 人类输入 | 必须 |
| SeedPaper（种子文献） | `Methodology / Structure / Citations` | 用户提供 | 可选 |
| —（投递物普查） | question/draft/code/data/results/logs/venue_spec 等 11 类 | workspace root / `intake/` | 可选 |

### 2.2 检索的 schema 定义
- `semantic/Paper.md`——种子论文作为 `Paper` 节点（`title / arxiv_id / research_question / domain`，注意 `paradigm / evidence_type` 填充率 0%，本阶段不依赖）。
- `application/ResearchQuestion.md`——冻结后的 Q-id 落点（`question / paper_id / problem_category`）。
- `application/ProblemCategory.md`——问题聚类编码（`code / label / n_papers`）。

### 2.3 输入产物文件
`AGENT_DOC.md`（`DISCIPLINE_CONTEXT`）、`kernel/config/phasegraph.json`（26 节点图）、用户投递物。

## 3. Skills 转移函数

| skill | 角色 | 输入 → 输出 |
|---|---|---|
| `support/intake-triage` | Phase 0 companion | 投递物 → `INTAKE_MANIFEST.json` |
| `meta-skills/domain-signature` | Phase 1a OPTIONAL | 问题文本 → `domain-signature-hint.json` |
| `auto-pipeline` Phase 0/1 | 编排 | Q-id → `REP.json`（研究目标与 fallback） |

### 原始 prompt 原文（逐字）
- "Analyze the problem statement and extract a structured domain signature."
- "Never hard-code domain-to-signature mapping. The signature is extracted from the problem text, not from a classification table."
- "Domain signature is not a label. It's a set of probabilistic signals. A problem can have mixed signatures (e.g., computational biology = CS + biology)."
- "If confidence < 0.5, use the default `general` signature — no domain-specific adaptation."
- "The signature is always provisional. Downstream skills can refine it if they detect better signals."
- 抽取维度："Evidence type: What kind of evidence does this domain typically accept?" / "Methodology patterns: What research methods are standard in this domain?" / "Writing conventions: What writing style does this domain expect?" / "Citation norms: How are citations formatted in this domain?" / "Failure modes: What are the typical failure modes in this domain?"
- intake-triage："inherited artifacts still face every mechanical gate at their boundary (an inherited RESULT.json still needs the ladder/ablation/parity evidence...)"; "Intake never bypasses gates: `inherit` means 'start from this artifact', not 'trust this artifact'."; "Never read full drafts into context; sample heads/structure."
- 冻结："INV-G1 is non-negotiable. The Q-id is frozen at Phase 0 and must be referenced in every downstream phase."

### 推理逻辑（解释）
规则信号匹配（domain/methodology/evidence/output keywords）→ 六维概率签名 → 置信度判定 → 低置信回落 `general`。这一步是"不硬编码"与"可追溯锚点"两条纪律的起点。

## 4. 输出

### 4.1 知识节点
- `ResearchQuestion`（Q-id 冻结，global）；`DomainProfile`(origin=rule，paperapp)
- 六维 profile：domain_profile / methodology_profile / writing_profile / failure_mode_profile / data_profile / confidence

### 4.2 产物文件
`refine-logs/FINAL_PROPOSAL.md`（含 Problem Anchor）、`refine-logs/PROBLEM_HASH.txt`（SHA256）、`refine-logs/domain-signature-hint.json`、`refine-logs/INTAKE_MANIFEST.json`、`INTAKE_REPORT.md`、`.sciforge/audits/REP.json`。

## 5. 门与有界回退

| 门 | 判据 | 阈值 | 失败去向 |
|---|---|---|---|
| INV-G1 | Q-id 冻结且各阶段引用一致 | — | BLOCKED，重新锚定 |
| 问题内容哈希 | `PROBLEM_HASH.txt` 比对 | SHA256 相等 | `FAIL(problem_content_rewritten)` → 只能 KILL 回 Phase 2 换题 |
| 签名置信门 | `confidence < 0.5` | 0.5 | 回落默认 `general` |
| intake 门 | 无（planning artifact） | — | OUT-OF-SCOPE 以 scope statement 拒绝 |

**有界回退**：Phase 1 → Phase 0（缺 Human prompt → Request user input）；domain-signature 为 OPTIONAL，失败只记 WARN 继续。hint 永远不作为 fallback signature（sole writer 是 Phase 1b）。

## 6. 事实 / 解释 / 不确定
- **事实**：上述 prompt 原句、置信阈值 0.5、INV-G1 冻结机制。
- **解释**：把 0/1/1a 合并为"问题锚定"阶段；把"不硬编码 + 可追溯锚点"作为该阶段的设计意图。
- **不确定**：`domain-signature` 文件内部 frontmatter 写产出 `domain-signature-hint.json`，而 Output Shape（L154–157）写 `domain-signature.json` + report.md——按 sole-writer 设计以 hint 为准（见链式总结 §待核实）。
