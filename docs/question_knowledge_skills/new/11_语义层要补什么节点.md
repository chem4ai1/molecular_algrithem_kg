# 11 · 语义层要补什么「节点」

按 `01`–`10` 的方法论要求倒推。**关键区分**：不是所有必需信息都该建成节点。

## 判断标准（沿用既有三条）

| 判据 | 结论 |
|---|---|
| 一句话能说清、不需要被别处引用 | **属性** |
| 只描述「这一对」对象的组合 | **边属性** |
| 需要独立 id 被引用 / 跨论文聚合 / 作为评分对象 | **节点** |

## 九项必需信息的三分

| # | 必需信息 | 落法 | 为什么 |
|---|---|---|---|
| 1 | paradigm | Paper 属性 | 枚举值，不被引用 |
| 2 | evidence_type | Paper 属性 | 同上 |
| 3 | seeds / sample_size / train_scale | `model_results[]` 行属性 | 属于该数值本身 |
| 4 | protocol（seed/划分/脚本/epoch） | **EVALUATED_ON 边属性** | 同一基准在不同论文协议不同，是「论文×基准」的 |
| 5 | **contributions[]** | **新节点 Contribution** | 需被实验组/指标引用，且是「每条贡献是否有支撑」的评分单位 |
| 6 | contribution_link（指标→贡献） | 属性（填 C1/C2 引用 Contribution.id） | 关联边在应用层重建 |
| 7 | section_map | Contribution 属性 `section` | 章节归属是贡献的一条属性 |
| 8 | assumptions[] | Algorithm 属性（语义层）+ 应用层 Assumption 节点 | 语义层存原文，逐条判定属任务层 |
| 9 | Figure.caption | Paper 属性 `figures[]` | 图注是论文内部一致性，不是跨论文知识 |
| 10 | RELATED_TO.context / doi / venue | 边属性 | 只描述这一条引用 |

## 结论：必须新增 2 个节点类

### 节点 1 · Contribution（论文声称的贡献）

```
id        contribution:<arxiv_id>:<n>     例 contribution:2411.06608:1
属性      statement      一句话贡献（≤80 字）
          kind           method | data | analysis | system
          why_not_before 数组，每条 ≤40 字，需覆盖技术约束/理论盲点/数据可得性 中至少 2 类
          section       出现在哪一节（Introduction / Method / …）
          claimed_strength  proven | supported | suggests（论文自己的措辞）
关系      Paper -DECLARES-> Contribution
          Contribution -TESTED_BY-> ExperimentArm
抽取阶段  E1
规模      783 篇 × 约 3 条 ≈ 2350
```

**为什么必须是节点而不是数组**：
`05` 要求「每条贡献都要有实验支撑」。如果贡献只是 Paper 的属性数组，
实验组无法指回「我验证的是第几条」，这个检查就做不了。

### 节点 2 · ExperimentArm（实验组）

```
id        experiment:<arxiv_id>:<kind>:<n>   例 experiment:2411.06608:baseline:0
属性      kind       main | baseline | ablation | hyperparam
          name       组名（如 "GDSS" / "-w/o geometry attention" / "lr=1e-3"）
          config     配置（超参、数据规模、运行次数）
          n_seeds    该组跑了几个 seed
关系      Paper -RUNS-> ExperimentArm
          ExperimentArm -ON-> Benchmark
          Contribution -TESTED_BY-> ExperimentArm
引用方式  Benchmark.model_results[].arm = "baseline:0"（指向本论文的组）
抽取阶段  E3（协议）+ E4（数值归属）
规模      783 篇 × 约 5 组 ≈ 3900
```

**为什么必须是节点**：`05` 的强制矩阵（baseline ≥3、消融 ≥2、超参 ≥3 点）
要能逐组清点。当前 `model_results[]` 只是一行行数值，无法表达
「这一行属于 baseline 还是消融」，矩阵检查只能靠 LLM 重新读原文。

## 明确不加节点的 7 项（只加属性/边属性）

| 项 | 落法 | 不加节点的理由 |
|---|---|---|
| paradigm | `Paper.paradigm` | 枚举，一篇一个，不被引用 |
| evidence_type | `Paper.evidence_type` | 同上 |
| protocol | `EVALUATED_ON` 边属性 | 同一基准跨论文不同协议，属「论文×基准」 |
| seeds / sample_size / train_scale | `model_results[]` 行属性 | 属于该数值 |
| contribution_link | `Benchmark.metrics[].contribution = "C1"` | 字符串引用即可，边在应用层 |
| section_map | `Contribution.section` | 一条属性 |
| Figure.caption | `Paper.figures[]` | 论文内部一致性，不跨论文聚合 |

**判断依据**：这 7 项都不需要被**别的对象**引用，也不作为**评分单位**。
建节点会让图从 6001 膨胀到 2 万+，而查询能力没有增加。

## 应用层再加 1 个（不是语义层）

`Assumption`（假设）：

| | |
|---|---|
| 语义层存 | `Algorithm.assumptions[]`（原文列表，属性） |
| 应用层建 | `Assumption` 节点（reproduction 任务） |
| 关系 | `Algorithm -ASSUMES-> Assumption`；`Assumption -TESTED_BY-> ExperimentArm` |
| 为什么分两层 | 「论文写了什么假设」是客观事实；「这条假设有没有被验证」是任务判定 |

这与 `Limitation` 的处理一致：语义层存文本，应用层提升为节点供逐条判定。

## 图结构变化

| | 现在 | 补充后 |
|---|---|---|
| 语义层类 | 6 | **8**（+ Contribution / ExperimentArm） |
| 语义层关系 | 9 | **13**（+ DECLARES / RUNS / TESTED_BY / ON） |
| 节点数 | 6001 | 约 **12250**（+2350 +3900） |
| 应用层类 | 6 | **7**（+ Assumption） |

## 兼容性与代价

| 项 | 处理 |
|---|---|
| `stable_key()` | 不变，新节点不参与 method SAU 指纹，历史 spec_hash 不失效 |
| 现有 5 套复现产物 | 继续可读；新节点缺失时判定降级为 qualitative |
| 抽取成本 | E1 +1 次字段、E3 +1 段、E4 +2 字段，**不新增 LLM 阶段** |
| 图查询性能 | 节点翻倍，邻接索引仍是 O(1)；但 `by_type` 全扫会变慢，需加类型索引 |
| 与既有类的重复 | 已核对：Contribution ≠ `Algorithm.problems_solved`（后者是能力，前者是声明） |

## 与既有类的边界（避免建重复）

| 容易混 | 区别 |
|---|---|
| Contribution vs `Algorithm.problems_solved` | 前者是「本篇宣称的贡献」，后者是「方法能解决什么问题」 |
| Contribution vs SAU | 前者是叙事单位（论文说的），后者是验证单位（可判定） |
| ExperimentArm vs `Benchmark.model_results[]` | 前者是「组」，后者是「组里的行」 |
| ExperimentArm vs 应用层 `ExperimentNode` | 前者是论文做了什么，后者是本次复现跑了什么 |
