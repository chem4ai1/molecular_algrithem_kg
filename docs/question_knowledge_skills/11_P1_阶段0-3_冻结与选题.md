# P1 · 阶段 0–3 + 4broad/4targeted：冻结与选题

> 覆盖 26 节点：`0` Q-id 冻结 → `1` 问题分解/`REP.json` → `1a` domain-signature(hint) → `1b` domain-learner → `4broad` 广搜/gap → `2` idea-discovery → `2.5` 证伪 → `2.5b` 工程落地 → `3` novelty 收敛 → `4targeted` 定向检索。
>
> 语义层现状（实测）：`Paper.research_question` 100% 有值但**无冻结 id / 无 hash**；`algorithm:subclass_of` 1083 条但 `properties` 里只有 `kind` + `evidence` 两个键；`Paper.doi` 仅 2/808。
> 也就是说：**这一阶段的问题几乎全部是「已有文本很强，但不可判定」**。

## P1.2 本节小结（表外三件事）

1. **`research_question` 100% 覆盖是假的安全感。**
   它是一句自由文本，没有 id、没有 hash、没有「下游必须回引」的约束。
   DK-P1-01/02 之所以必须做，不是因为抽取不好，而是因为**文本无法被机器比对**。
   最小改动：在 `Paper` 上补 `problem_anchor`（B 类），**不新建 `ProblemAnchor` 类**。

2. **`SUBCLASS_OF` 已有 1083 条，但只带 `{kind, evidence}` 两个键。**
   `kind ∈ {extends, improves, replaces}` 已经有了，缺的是 `assumption_delta`（改进了哪条前提）。
   没有它，P3 的逻辑审计无法判断「改进是否真的成立」——这是一条边属性就能解决的（C 类），不要新建类。

3. **`Paper.year` 只有 2/808 有值。**
   DK-P1-14 的「前沿是否最新」在现有图上**算不出来**。
   在做任何 novelty 判断之前，必须先补 `year`（B 类，抽取期必填）。

## P1.4 反模式（本阶段看起来对但会出事）

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 为了让 gap「有支撑」，给未验证的 `RELATED_TO` 补上 `verified: true` | 引用审计的输入被污染，P4 的 `citation-audit` 必然假通过 | `verified` 只能由三层验证写入，抽取期一律 `false` |
| 把 `problem_anchor` 写进 `stable_key()` | 5 套已跑产物的 `spec_hash` 全部失效（`05` §5.5） | 新增属性只影响判定，不进指纹 |
| 认为「研究问题不清」是 LLM 能力问题，加重 prompt 就行 | 真正的问题是**没有机器可比对的锚**，prompt 再重也留不下痕迹 | 先加 `id + text_hash`，再改 prompt |
| 在 Phase 2 用「有没有人做过」这一句主观判断淘汰 idea | 判断权应该在 `gap_gate`（确定性），不在 LLM | Type-A 零 LLM 判定优先（P3 原则） |
| 允许人的 hypothesis 直接进 survivor 不必过 gap 校验 | 人类主权 ≠ 人类豁免 | 人的方向同样要 `gap_anchor`，或显式写 `exploratory_reason` |
