# 02 · 可迁移知识点（来自 27 个 SKILL 的机制摘录）

> 只摘「有阈值、有契约、有判定」的机制，不抄概念。每条给出：原机制 → 我方落点。

## K1 · 问题锚定冻结（INV-G1）

- **原文**：原始问题的 Q-id 必须记录在 `FINAL_PROPOSAL.md`，且**在每个下游产物中被引用**；
  不满足 → `BLOCK — re-anchor`。
- **目的**：防止中途跑去解一个更容易的问题。
- **我方落点**：`ReproSpec` 加 `problem_anchor`（Q-id + 文本 hash），写入
  `METHOD_LOCK.json`，并在 `SAU` / `rubric_tree` / `CLAIM_ANCHORS` 回引。

## K2 · 8 段方法注册表 + Section 3 hash-lock

- **原文**：8 段 schema；Section 3（Method Selection）锁定后写 `methods/REGISTRY_HASH.txt`，
  **看到结果后不可改**；Section 1 自带 `Frozen hash`。
- **我方落点**：`METHOD_LOCK.json` 从一个 hash 扩成「段级 hash 摘要」：
  Section 1 = problem anchor，Section 3 = method SAU 集合。

## K3 · 强制实验矩阵（与 Section 3 同锁）

| 项 | 要求 | 缺项后果 |
|---|---|---|
| Main experiment | ≥1 核心假设验证实验 | hash-lock 拒绝 |
| Baseline | **≥3**：SOTA 复现 + 经典 + naive（random/majority/identity） | hash-lock 拒绝 |
| Ablation | 逐创新组件 leave-one-out，**≥2 组** | hash-lock 拒绝 |
| Hyperparameter | ≥1 核心超参 × **≥3 值点**（或声明不敏感理由） | hash-lock 拒绝 |
| 产物 | 缺项 → `BLOCKED: experiment_matrix_incomplete` | — |

- **我方落点**：`METHOD_LOCK.json` 加 `experiment_matrix`；缺失即 `blocked`
  （当前 `lock` 只看 method SAU 是否存在）。

## K4 · 三档保真度 + 措辞规则

| 档 | 含义 | 允许措辞 |
|---|---|---|
| symbolic | 全链推导逐步机器验证 | `proven` / `established` |
| numerical | 数值检查确认行为符合预测 | `supported` / `confirmed numerically` |
| qualitative | 只有定性理由 | `suggests` / `consistent with` |

- **硬规则**：primary claim 至少 `numerical`；symbolic-only → `partial`；
  qualitative-only → `no`。**无 symbolic 不许 proven，无 numerical 不许 supported。**
- **我方落点**：`numeric` SAU 判定增补 `fidelity` 字段；`CLAIM_ANCHORS` 每条带 fidelity；
  生成侧 `ALLOWED_WORDING` 与之绑定。

## K5 · 证据充分性五项

| 检查 | 底线 | 失败标记 |
|---|---|---|
| Statistical power | 报样本量/训练规模 + 最小可检测效应 | `underpowered` |
| Effect size | 报效应量本身，且 > 1× between-seed std | `effect_within_noise` |
| Replication | ≥3 seeds 的 mean±std（lite ≥2）；单点不得支撑 PRIMARY | `single_seed` |
| Data-scale match | toy/synthetic 只能支撑「tested regime」级陈述 | `toy_overreach` |
| Baseline comparison | PRIMARY 需同条件 ≥1 baseline | `no_baseline` |

- 任一失败 → 该 claim 保真度**强制降到 qualitative 以下**，不得进正文。
- **我方落点**：`Evidence` / `LeaderboardEntry` 加这 5 个字段，`anchor` 阶段计算。

## K6 · 失败的 primary 不得改口

- **原文**：full fidelity 下预注册预期 FAIL 的 primary claim，不能被重述成通过的 claim，
  只能重标 `LIMIT` 或 `NEGATIVE`；替换 claim 必须按同一证据标准重新预注册；
  单点标定需敏感性扫描证明非刀锋。
- **我方落点**：`SAU_VERDICTS` 加 `retyped`（limit/negative），重述要求 `spec_hash` 变更留痕。

## K7 · 3 态 Critic（实验阶梯）

- **原文**：`GOOD`（相对增益 > max(min_gain, 0.15%)）/ `ENGINEER`（打平，≤2 轮）/
  `BAD`（更差，丢弃）；**必须先在子集复现 baseline**；
  只有严格优于**复现出来的** baseline 才升 full；**ties 不算赢**。
- **我方落点**：`sciforge/repro/ladder.py` 已实现
  （`GAIN_TOLERANCE_PCT=0.0015`、`MAX_ENGINEER_ROUNDS=2`），
  但**未接入 `lifecycle.execute`**；需在 `EXECUTION_LOG` 写 `ladder_state`。

## K8 · 消融规划 + AblCritic

- **原文**：planner 出 **5–6 个** plan（`SCIFORGE_ABLATION_MIN/MAX`），
  AblCritic 机械判定 `{GOOD|REFINE}`，规则「**新的必须严格优于旧的**」，ledger 单调。
- **我方落点**：从 `AlgorithmModule` 枚举创新组件，生成 ablation SAU/任务；当前完全缺失。

## K9 · 质量门 Type D + Type S

- **原文**：Type D（确定性）先跑，失败立即阻塞；Type S（语义）**必须引用具体证据位置**
  （文件 + 章节/行号），`"looks reasonable"` 不被接受。
- **我方落点**：`gates.py` 现有 7 门都是 Type D；需为「机制是否支撑」「指标方向」
  加 Type S 门，并要求引用 `sau_id` / `node_id`。

## K10 · 停滞检测

- **原文**：`RETRY_COUNTERS[key] > MAX_RETRIES[key]` → `STAGNATED` → Gate=FAIL，
  产出 stagnation report 并阻塞写作。
- **我方落点**：`lifecycle` 的 `blocked_by` 计数；同一原因 ≥3 次即 `stagnated`。

## K11 · 四类泄露审计

| 类型 | 含义 | OSS 状态 | **我方** |
|---|---|---|---|
| Type I 逻辑缺口 | 声称的结论不能从假设推出 | 启用 | **必须启用** |
| Type II 隐藏违规 | 实证方法暗中违反自身理论假设 | NOT_APPLICABLE | **必须启用** |
| Type III 代理不匹配 | 指标度量的不是核心贡献 | NOT_APPLICABLE | **必须启用** |
| Type IV 经验逃逸 | 数值验证跑出假设成立的 regime | 启用 | **必须启用** |

- **关键判断**：OSS 把 II/III 标为不适用，是因为它「无实验、无 benchmark」；
  我方有 benchmark 与数值，这两类恰恰最容易出问题（如拿 accuracy 证明
  「表示更好」，而不验证表示本身）。
- **我方落点**：新增 `leakage_audit`，输入 `SAU + Benchmark + 指标方向 + 数值`。

## K12 · 6 维逻辑审计 + 20 类问题

- **原文**：6 维一致性 + 20 类问题分类 + **3 轮上限**；
  通过标准「**零 FATAL/CRITICAL**」；**反例 pass 必做**（没找到也要记候选）；
  3 轮未过 → `NOT YET COHERENT` 升级，不许静默通过。
- **我方落点**：5 态之外加 `issue_class`（20 类子集）与轮次上限。

## K13 · 3 层引用验证

- **原文**：existence（DOI/arXiv/venue 真实存在）→ metadata（作者/年/venue/标题一致）
  → context（**被引论文是否真的支撑该论断**，最危险的一类）。
- **我方落点**：`RELATED_TO` 目前只是线索边；需加 `verified` 状态与 `context` 判定。

## K14 · 4 轴新颖性打分

- **原文**：`novelty×0.45 + feasibility×0.25 + relevance×0.15 + engineering_grounding×0.15`；
  `<0.6` 淘汰；`why_not_before` 需 3 条理由覆盖 ≥2 类（技术约束/理论盲点/数据可得性），
  否则 `why_not_before_weak` 扣 2 分。
- **我方落点**：生成任务选题打分（P2）。
